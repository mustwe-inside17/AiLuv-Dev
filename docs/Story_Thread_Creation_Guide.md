# AiLuv — คู่มือเล่า Story Thread ให้มิเกลสร้างลงเกม

ไฟล์นี้มีไว้ให้ปอนเล่าเส้นเรื่องเป็นภาษาคน ไม่จำเป็นต้องคิดชื่อตัวแปรหรือเขียนโค้ดเอง มิเกลจะนำเรื่องที่เล่ามาแตกเป็น `Story Thread`, `Story Node`, `Story Flag`, `Key Story Item`, เงื่อนไข, คำใบ้ และ Test Case ให้พร้อมส่งต่อ AI Dev

## คำศัพท์ที่ใช้ร่วมกัน

| คำ | ความหมาย |
| --- | --- |
| **Story Thread** | เส้นเรื่องหนึ่งตอน ตั้งแต่เริ่มจนถึงจุดจบของตอน เช่น “เสียงจากตู้เก็บของ” |
| **Thread Entry Trigger** | เหตุการณ์หรือเงื่อนไขที่ทำให้เส้นเรื่องเริ่มทำงาน |
| **Story Node** | ซีนหรือขั้นหนึ่งภายใน Story Thread |
| **Prerequisite** | สิ่งที่ต้องมีหรือทำสำเร็จก่อนเข้า Node |
| **Story Flag** | หลักฐานในเซฟว่ามีเหตุการณ์เกิดขึ้นแล้ว |
| **Key Story Item** | ของสำคัญที่เชื่อมตัวละครหรือใช้เปิดความจริง |
| **Story Reveal** | ความจริงที่ผู้เล่นได้รับจาก Node นั้น |
| **Grant** | Flag หรือ Item ที่ระบบมอบหลังผ่าน Node สำเร็จ |
| **Thread Complete Flag** | Flag ที่ระบุว่าจบเส้นเรื่องตอนนั้นแล้ว |

Story Thread แบ่งเป็น 2 หมวดหลัก:

- **AiLuv Life** — เรื่องสั้นในชีวิตประจำวันของเมือง จบในตัวเองหรือทิ้งเบาะแสบาง ๆ ไปยัง Canon
- **AiLuv Story** — เส้น Canon หลักที่เกี่ยวกับอดีต ความลับ ความขัดแย้ง และชะตาของเมือง

โครงสร้างมาตรฐาน:

```text
Thread Entry Trigger
  → Story Node 1
  → Story Node 2 / ได้ Key Story Item
  → Story Node 3 / นำ Key ไปหาคนที่เกี่ยวข้อง
  → Story Reveal
  → Thread Complete Flag
```

## วิธีเล่าแบบสั้นที่สุด

ปอนเริ่มเล่าได้ด้วยประโยคนี้:

> มิเกล ผมอยากทำ Story Thread เรื่อง ______ เริ่มเมื่อผู้เล่น ______ กับตัวละคร ______ ที่ ______ จากนั้นผู้เล่นจะพบ/ได้รับ ______ และต้องนำไปหา ______ เพื่อค้นพบว่า ______ แต่ยังห้ามเปิดเผยเรื่อง ______

ข้อมูลส่วนไหนยังคิดไม่ออกให้เขียนว่า **“ให้มิเกลช่วยเสนอ”** ได้ มิเกลจะเติมทางเลือกที่เหมาะกับเนื้อเรื่องและไม่ขัด Canon ให้ปอนเลือกก่อนลงเกม

## Thread Entry Trigger เลือกได้จากอะไรบ้าง

Trigger หนึ่งเรื่องใช้หลายเงื่อนไขร่วมกันได้ โดยควรระบุว่าเป็น **AND** (ต้องครบทุกข้อ) หรือ **OR** (อย่างใดอย่างหนึ่งก็พอ)

| ประเภท Trigger | ตัวอย่าง | เหมาะกับ |
| --- | --- | --- |
| **Character** | กำลังคุยกับเฟียร์ | เรื่องที่ผูกกับตัวละครคนหนึ่ง |
| **Location** | อยู่ที่ Iron Paradise | เหตุการณ์เฉพาะสถานที่ |
| **Relationship** | Love ≥ 30 หรือ Trust ระดับ 2 | ความลับส่วนตัวที่ต้องสนิทก่อน |
| **Previous Flag** | ผ่าน `radio.found` แล้ว | บังคับลำดับเรื่องไม่ให้ข้ามตอน |
| **Thread Complete** | จบเส้นเรื่องของมาร์คัสก่อน | เชื่อมเรื่องข้ามตัวละคร |
| **Owned Key** | ถือบัตรพนักงานปริศนา | เริ่มปฏิกิริยาเมื่อมีหลักฐาน |
| **Conversation Turns** | คุยทั่วไปกับเฟียร์ 1–3 รอบ | ทำให้เหตุการณ์ดูเกิดขึ้นเอง |
| **Topic / Intent** | ผู้เล่นพูดถึงผี เสียง หรือตู้ | ให้การคุยอิสระเป็นตัวเปิดเรื่อง |
| **Player Action** | เปิดตู้ ตรวจของ หรือยื่นของให้ดู | ซีนที่ต้องลงมือทำ |
| **Time / Day** | หลัง 22:00 หรือวันศุกร์ | เรื่องกลางคืน ตารางงาน หรือเทศกาล |
| **Activity Result** | ทำงาน/ออกกำลังกาย/ออกเดตเสร็จ | ผูกเรื่องเข้ากับเกมเพลย์อื่น |
| **Message / Social / Mail** | อ่านโพสต์หรือได้รับข้อความ | เปิดเรื่องจากโลกนอกหน้าแชท |
| **Random Chance** | โอกาส 25% เมื่อเงื่อนไขครบ | เหตุการณ์บังเอิญที่เล่นซ้ำได้ |
| **Cooldown / Visit Count** | พบตัวละครครบ 3 ครั้ง | คุมจังหวะไม่ให้เรื่องมารัวเกินไป |

### กติกาเลือก Trigger ที่สนุกและไม่ทำให้ผู้เล่นงง

1. Trigger ลับควรเริ่มจากพฤติกรรมธรรมชาติ เช่น ไปหาและคุยกับตัวละคร ไม่ควรบังคับให้เดาคำลับเพียงคำเดียว
2. ถ้าใช้ Love/Trust ให้สมุดบอกอย่างน้อยว่า “ยังไม่สนิทพอ” หรือแสดงความคืบหน้า อย่าซ่อนตัวเลขแล้วให้ผู้เล่นเดา
3. ถ้าใช้สุ่ม ต้องมี `pity` หรือจำนวนครั้งสูงสุดที่รับประกันว่าจะเกิด เช่น ไม่เกินการเยี่ยมครั้งที่ 3
4. ทุก Text Trigger ควรมีปุ่มหรือคำใบ้สำรอง เมื่อระบบจับภาษาผู้เล่นไม่สำเร็จ
5. Trigger ที่เกิดครั้งเดียวต้องตรวจ Flag เดิมเสมอ เพื่อไม่แจก Key หรือปลดเรื่องซ้ำ
6. AI ทำหน้าที่แสดงบทพูด แต่ Code เป็นผู้ตรวจ Trigger และบันทึก Flag/Item เท่านั้น

## วิธีเล่าแต่ละ Story Node

ในแต่ละซีน ปอนเล่าเพียง 6 เรื่องนี้ก็พอ:

1. **ใครและที่ไหน** — ตัวละครกับ Location
2. **ผู้เล่นทำอะไร** — คุย ตรวจ เปิด หยิบให้ดู หรือเลือกคำตอบ
3. **ต้องผ่านอะไรมาก่อน** — Flag, Key, Love/Trust หรือเวลา
4. **ตัวละครควรถ่ายทอดอะไร** — ข้อเท็จจริง ไม่จำเป็นต้องเขียนบทพูดตายตัว
5. **ยังห้ามพูดอะไร** — ป้องกัน AI เปิดความจริงข้ามตอน
6. **ผ่านแล้วได้อะไร** — Flag, Key, คำใบ้ หรือ Node ถัดไป

ตัวอย่างรูปแบบสั้น:

```markdown
ซีน: เปิดตู้เก็บของ
ใคร/ที่ไหน: เฟียร์ / Iron Paradise
ผู้เล่นทำอะไร: เปิดตู้พร้อมเฟียร์
ต้องมีก่อน: เคยได้ยินเสียงจากตู้
ความจริงที่พูดได้: พบวิทยุติดสติกเกอร์ NYX และเฟียร์จำได้ว่าเอรินเคยนำอุปกรณ์มาที่ยิม
ห้ามพูด: ความเชื่อมโยงกับ Midnight City และตัวจริงของ NYX
ผ่านแล้วได้: วิทยุ NYX และคำใบ้ให้ไปหาเอริน
```

## ตัวอย่างครบ — Story Thread ตอนวิทยุ

### ภาพรวม

- **ชื่อ:** เสียงจากตู้เก็บของ
- **Thread ID:** `nyx_radio`
- **Player Promise:** เหตุการณ์เล็ก ๆ ระหว่างคุยกลับกลายเป็นเบาะแสของอดีตตัวละคร
- **Key Story Item:** `key_nyx_radio`
- **จุดจบตอน:** เอรินเล่าความเชื่อมโยงกับลูคัสและ Midnight City แต่ยังไม่เปิดเผยตัวจริง NYX

### Thread Entry Trigger ที่เกมรุ่นปัจจุบันใช้จริง

```yaml
character: fia
location: gym
minimum_love: 0
required_flags: none
activation:
  - ผู้เล่นพูดถึงเสียง ผี หรือตู้เก็บของ
  - หรือกดปุ่ม "ถามถึงเสียงในตู้" จากเมนู Key
```

ปัจจุบันเรื่องไม่ได้เริ่มเองหลังคุย 1–3 รอบ หากต้องการให้เฟียร์เป็นฝ่ายได้ยินเสียงและโยนเรื่องขึ้นมาเอง ต้องให้ Dev เพิ่ม Trigger แบบ `conversation_turns` หรือ Story Director ก่อน

### เวอร์ชัน Trigger ที่แนะนำสำหรับอนาคต

```yaml
all_of:
  - character: fia
  - location: gym
  - flag_not_set: radio.noise_heard
any_of:
  - conversation_turns: 1-3
  - topic_intent: ghost_or_locker_noise
  - player_pressed_story_hint: true
guarantee_by_turn: 3
```

ผลคือผู้เล่นสามารถค้นพบเรื่องจากการคุยอิสระ และยังมีปุ่มช่วยเมื่อเหตุการณ์ไม่เกิดหรือ AI จับบริบทไม่ได้

### Story Nodes

| ลำดับ | Story Node | Prerequisite | เหตุการณ์ | Grant |
| --- | --- | --- | --- | --- |
| 1 | `radio_hear_noise` | เฟียร์ + ยิม, Love 0 | ได้ยินเสียงซ่าจากตู้ | `radio.noise_heard` |
| 2 | `radio_open_locker` | `radio.noise_heard` | เปิดตู้และพบวิทยุ NYX | `radio.found`, `key_nyx_radio` |
| 3 | `radio_erin_recall` | `radio.found` + ถือวิทยุ + พบเอริน | เอรินจำวิทยุและเล่าอดีตบางส่วน | `radio.erin_recalled`, `radio.episode_complete` |

### พฤติกรรมเมื่อมอบ Key

- **เอริน:** คนถูกต้อง เมื่อเงื่อนไขผ่านจึงเล่าความจริงตาม Facts
- **เฟียร์:** รู้เพียงว่าเจอด้วยกันและเอรินอาจจำได้
- **มิเกล/ตัวละครอื่น:** ตอบตามบุคลิกว่าไม่รู้ พร้อมชี้กลับไปยังเบาะแสที่ผู้เล่นมี
- **ลูคัส:** อาจมีท่าทีผิดปกติได้ แต่ห้ามยืนยันอดีตหรือเปิดเผย Canon ก่อนถึง Node ของเขา
- มอบให้ผิดคนแล้ว Key ต้องไม่หาย และไม่สร้าง Flag สำเร็จ

## สิ่งที่มิเกลจะส่งกลับหลังปอนเล่า

มิเกลจะจัดทำให้ครบเป็นลำดับดังนี้:

1. สรุป Story Thread และอารมณ์ของตอน
2. แยก Thread Entry Trigger เป็นเงื่อนไข AND/OR
3. แตก Story Nodes และลำดับ Prerequisite → Grant
4. ตั้งชื่อ `thread_id`, `node_id`, `flag_id`, `item_id` ที่ไม่ซ้ำ
5. กำหนด Key Story Item และนโยบายมอบถูกคน/ผิดคน
6. ทำ Character Knowledge ว่าใครรู้ รู้บางส่วน สงสัย หรือห้ามรู้
7. ระบุ Facts, Forbidden Reveals, Repeat Direction และคำใบ้ในสมุด
8. ใส่ข้อมูลใน Story Flag CMS พร้อมสถานะ `READY_TO_BUILD`
9. เขียน Test Cases สำหรับ Success, Locked, Wrong Character, Repeat, AI Failure และ Reload
10. เมื่อตกลงเนื้อเรื่องแล้ว จึงแก้ Code, ทดสอบ และส่ง ZIP เวอร์ชันใหม่

## Checklist ก่อนบอกให้มิเกลลงเกมจริง

- [ ] จุดเริ่มเรื่องเกิดจากสิ่งที่ผู้เล่นมีโอกาสทำจริง
- [ ] ผู้เล่นรู้หรือพอเดาได้ว่าควรทำอะไรต่อ
- [ ] ทุก Node ระบุสิ่งที่ต้องมีก่อนและสิ่งที่ได้รับหลังผ่าน
- [ ] ตัวละครแต่ละคนรู้ไม่เท่ากันอย่างมีเหตุผล
- [ ] ระบุความจริงที่พูดได้และสิ่งที่ยังห้ามเปิดเผย
- [ ] Key ไม่หายเมื่อให้ผิดคน เว้นแต่ปอนตั้งใจให้เป็นของใช้ครั้งเดียว
- [ ] Love/Trust ไม่ใช่ตัวเลขสูงโดยไม่มีเหตุผลทางเนื้อเรื่อง
- [ ] มีทางสำรองเมื่อ AI ไม่เข้าใจข้อความอิสระ
- [ ] ตอนจบให้คำตอบบางส่วนและทิ้งแรงอยากรู้สำหรับ Thread ต่อไป
- [ ] Canon ใหม่ได้รับการยืนยันจากปอนก่อนนำลงเกม

## ประโยคเริ่มต้นที่พร้อมใช้

> มิเกล ผมมี Story Thread ใหม่ชื่อ “...” อยากให้เริ่มเมื่อผู้เล่น... จากนั้นเกิดประมาณ ... ซีน Key Item คือ... คนที่เกี่ยวข้องจริงคือ... ตอนจบอยากเปิดเผยว่า... แต่ยังห้ามพูดเรื่อง... ส่วน Trigger และเงื่อนไขที่เหลือให้มิเกลช่วยออกแบบให้สนุกและไม่ทำให้ผู้เล่นงง

จากข้อความนี้ มิเกลสามารถเริ่มแตก Thread ให้ปอนตรวจ แล้วค่อยนำข้อมูลที่อนุมัติแล้วลง Google Sheet และ Code จริงได้
